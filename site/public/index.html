01

The exposure window is closing

More vulnerabilities are published every year, and attackers use them sooner. A response that waits for a human to read an advisory now starts too late.

What that means for response. When a fix exists, PATCH opens the pull request that pins it, in minutes rather than at the next triage meeting. When exploitation comes before the fix, patching cannot help, so the pre-approved containment steps do the work: safe mode, credential revocation, paging.

05

How it works

A single CLI, patchnow, runs on a schedule in CI or as a daemon. Policy lives in your repository as patch.yml. Nothing destructive happens until you set armed: true.

1 · Match

Lockfiles are parsed for exact versions and queried in batches against OSV.dev. Each finding carries its advisory severity, the smallest fixed version, its KEV status and its EPSS score.

2 · Decide

Triggers in patch.yml are evaluated: any entry can fire, and every key within an entry must match. Ignores need a reason and can expire. Findings that already fired are deduplicated.

3 · Act

Actions run in order: a pinned-version pull request, safe mode on Render, Vercel or a webhook, credential revocation, then notifications that include the PR link.

4 · Record

Every run, decision and action is appended to .patchnow/audit.jsonl. SARIF output feeds GitHub code scanning.

Quick start

$ npm install -g https://github.com/patchprojectx/patch/releases/download/v0.1.0/patchnow-0.1.0.tgz
$ patchnow init            # writes patch.yml (dry run until armed: true), adds .patchnow/ to .gitignore
$ patchnow scan --fail-on kev
$ patchnow run             # scan → policy → actions (dry run)

Requires Node.js 20 or newer. The only runtime dependency is yaml.

patch.yml

Unknown keys are rejected, so a typo cannot silently weaken the policy. Secrets are never stored in the file: any key ending in _env names an environment variable.

version: 1
armed: false                # nothing destructive happens until true

scan:
  paths: ["."]
  include_dev: false
  runtimes: auto            # auto | off
  epss: true
  max_depth: 4

packages: { only: [], exclude: [] }

ignore:
  - id: CVE-2020-28500       # OSV id, GHSA id or CVE
    reason: "never called with user input"   # required
    expires: 2026-12-31      # fires again after this date
    packages: [lodash]

triggers:                   # ANY entry fires; keys inside an entry are ANDed
  - kev: true
  - severity: critical       # minimum: low | moderate | high | critical
  - epss: ">0.5"

actions:                    # run in order on the findings that fired
  - pin_patch: { base: main }
  - safe_mode:
      when: { kev: true }
      provider: render_deploy_hook
      url_env: RENDER_MAINTENANCE_DEPLOY_HOOK
  - notify:
      slack: { url_env: SLACK_WEBHOOK_URL }

state: { path: .patchnow/state.json, refire_after_days: 0 }
audit: { path: .patchnow/audit.jsonl }
Trigger keyTypeMatches when
kevboolThe finding's CVE is in the CISA KEV catalog.
severitylow|moderate|high|criticalAdvisory severity is at least this level (medium is an alias for moderate).
cvss">=9.0"The CVSS v3 base score satisfies the comparison (> >= < <= ==).
epss">0.5"The highest EPSS probability among the finding's CVEs satisfies the comparison.
ecosystems[npm, PyPI, …]The finding's ecosystem is listed (case-insensitive).
packages[name, …]The package name is listed.
include_devboolfalse excludes dev dependencies.
runtimeboolRuntime findings (node, php, go) only, or never.
has_fixboolA fixed version is, or is not, published.

Any action can carry when: with the same keys to narrow it further. Dedupe key: ecosystem|package|version|advisory. After an armed run acts on a key, that key does not fire again unless refire_after_days is above 0. Dry runs record no state.

Actions

ActionOptionsBehaviour
pin_patchbranch_prefix · base · remote · push · open_pr · draft · labels · token_env · repo · allow_dirty · author_name · author_emailRaises each package to the smallest version that clears every fired advisory. For npm: npm install pkg@X --package-lock-only --ignore-scripts for direct dependencies, and overrides for transitive ones. Also edits requirements.txt pins and uses pnpm, go, cargo or composer when installed. Verifies by re-parsing the lockfile (npm: also npm ls), then commits on patchnow/<date>-<hash>, pushes, and opens a pull request through the GitHub REST API. Refuses to run on a dirty working tree.
safe_modeprovider · url_env · secret_env · method · token_env · project_id · deployment_id · team_idrender_deploy_hook POSTs a Render deploy hook. vercel_promote calls POST /v10/projects/{id}/promote/{deployment}. webhook sends JSON with an optional HMAC-SHA256 X-Patchnow-Signature.

GitHub Action

patchprojectx/patch is a composite action (action.yml at the repository root). It runs patchnow run --sarif, keeps .patchnow/ between runs with actions/cache, and uploads SARIF to code scanning. Pin @v0.1 for the latest v0.1.x, or @v0.1.0 for an exact release.

on:
  schedule: [{ cron: "*/15 * * * *" }]
  workflow_dispatch:
permissions: { contents: write, pull-requests: write, security-events: write }
jobs:
  patchnow:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: patchprojectx/patch@v0.1
        with: { config: patch.yml }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

Inputs: config · working-directory · dry-run · sarif · upload-sarif · github-token · persist-state

Security model: what leaves your machine

  • To api.osv.dev: package names, versions and ecosystems.
  • To api.first.org: CVE identifiers, for EPSS scores. Disable with scan.epss: false or --no-epss.
  • From cisa.gov: the public KEV catalog, cached locally for 6 hours.
  • Never sent: source code, file contents beyond name and version, environment variables. Secrets are referenced only by environment-variable name and redacted from error URLs.
  • Least surprise: dry run by default. Revocation needs armed: true and confirm: true. Lockfile updates run with --ignore-scripts. PATCH never merges anything; a human reviews the pull request.
  • This website: the checker sends only name and version pairs to OSV. No cookies, no analytics.

Limitations (v0.1)

  • Coverage is OSV's coverage. Matching is by package and version only; there is no reachability analysis.
  • A package.json without a lockfile, or a go.sum-only project, can over-report. Ranges in requirements.txt are skipped.
  • The minimum fixed version can still be a breaking change. Run your tests on the pull request.
  • The end-to-end test covers the npm update path. The pnpm, Go, Cargo and Composer editors call the native tools but are not covered by it. yarn.lock and poetry.lock are reported for manual update.
  • Pull requests opened with the default GITHUB_TOKEN do not trigger other workflows. Use a GitHub App or a fine-grained PAT if CI must run on them.
  • Node.js and PHP runtime checks use a hand-curated advisory table, not a live feed. Go is matched live through OSV.
  • Windows and SBOM inputs (CycloneDX, SPDX) are not supported yet.
